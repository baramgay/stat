이번 세션 작업 (버그픽스 + 폴리싱)

① 데이터셀 텍스트 회색 — ForegroundRole 근본 수정

근본 원인: Qt 모델 data()가 ForegroundRole을 반환하지 않으면, stylesheet QTableView::item { color }는 무시되고 시스템 팔레트 기본(회색)이 나온다. stylesheet alone으로는 절대 해결 안 됨.

변경 파일

파일변경 내용
ui/models/spss_grid_model.py _COLOR_TEXT = QColor("#111111") 상수 추가.
data() outside 분기 + 정상 데이터 셀 분기 양쪽에
if role == Qt.ItemDataRole.ForegroundRole: return QBrush(_COLOR_TEXT) 추가
ui/data_view.py stylesheet color #1a1a2e → #111111 (모델과 일치) 
# spss_grid_model.py — data() 메서드 내 두 곳에 추가
_COLOR_TEXT = QColor("#111111")   # 흰 배경 대비비 ~20:1

# outside 분기 (가상 빈 셀)
if role == Qt.ItemDataRole.ForegroundRole:
    return QBrush(_COLOR_TEXT)

# 정상 데이터 셀 분기 (ToolTipRole 직전에 삽입)
if role == Qt.ItemDataRole.ForegroundRole:
    return QBrush(_COLOR_TEXT)

✅ 교훈: Qt에서 텍스트 색상은 반드시 모델의 ForegroundRole로 제어. stylesheet color는 모델이 ForegroundRole 미반환 시 시스템 팔레트에 덮어씌워진다.

핵심 함정 · 확인된 패턴

Qt ForegroundRole 우선순위
모델 data()가 ForegroundRole을 반환하지 않으면 stylesheet color:는 무시됨. 텍스트 색상은 항상 모델에서 제어. QAbstractTableModel 서브클래스 작성 시 ForegroundRole 분기 필수.
비동기 다이얼로그 내 QMessageBox 블로킹
테스트에서 _run() 직접 호출 시 오류 발생하면 QMessageBox.critical이 블로킹 → monkeypatch.setattr(dlg, "_start_analysis", fake_fn)으로 우회.
PySide6 QTabBar.ButtonPosition
PySide6 6.x에서 QTabBar.RightSide AttributeError → QTabBar.ButtonPosition.RightSide 사용.
spec_utils invalid missing_policy 처리
parse_common_spec() 내 MissingPolicy(mp)는 unknown 문자열이면 ValueError → try/except → LISTWISE fallback 필수.
include_missing=True 시 missing_n 산출 위치
LISTWISE가 NaN 행을 제거하므로, missing_n은 prepared.data가 아닌 dataset.data 원본에서 직접 카운트.
run.bat 실행 방식
python -m nuristat은 설치 없이 동작 안 함. C:\업무\통계패키지\nuristat\run.bat 사용: PYTHONPATH=src python src\nuristat\main.py.
